Реальное приложение работает в нескольких окружениях: на ноутбуке разработчика, на тестовом сервере и в production. В каждом окружении — своя база данных, свои пароли, свой уровень логирования. Spring Boot решает эту проблему через механизм профилей и внешней конфигурации: один JAR-файл деплоится везде, поведение определяется конфигурацией снаружи. В этой статье вы освоите полный арсенал инструментов — от базового `@Value` до типобезопасных `@ConfigurationProperties` с валидацией — и получите production-ready конфигурацию для вашего проекта.

## 2. Зачем нужна профессиональная конфигурация

> **Уровень: Intern**

Ты написал приложение для управления задачами. Всё работает локально. Пришло время деплоить. И тут начинаются вопросы.

### Три реальные проблемы

**Проблема 1: Пароль прямо в коде**

Java

```
// ⛔ Реальный антипаттерн — встречается в десятках репозиториев на GitHub
@Configuration
public class DatabaseConfig {
    @Bean
    public DataSource dataSource() {
        HikariConfig config = new HikariConfig();
        config.setJdbcUrl("jdbc:postgresql://prod-db.company.com:5432/tasks");
        config.setUsername("app_user");
        config.setPassword("SuperSecret$2024!"); // ← уйдёт в Git навсегда
        return new HikariDataSource(config);
    }
}
```

Этот код попадёт в Git. История коммитов хранится вечно. Даже если удалишь пароль в следующем коммите — он останется в истории, и любой с доступом к репозиторию сможет его найти через `git log --all -p`.

**Проблема 2: Один конфигурационный файл для всех окружений**

В разработке нужна H2 (встроенная БД, не требует установки). В production — PostgreSQL. Если в `application.yml` прописан PostgreSQL — локально ничего не запустится без настройки сервера. Если H2 — production не поднимется.

**Проблема 3: Включить фичу только в production**

Новый алгоритм приоритизации задач нестабилен. Нужно включить его только в prod, проверить на реальных данных и быстро откатить — без перекомпиляции и пересборки артефакта.

> Если ты устраиваешься в компанию и видишь один `application.yml` без профилей — это красный флаг архитектуры.

## 3. application.properties vs application.yml

> **Уровень: Intern/Junior**

Spring Boot поддерживает два формата. Покажем одну и ту же конфигурацию рядом:

properties

```
# application.properties — плоский формат
server.port=8080
spring.application.name=task-service
spring.datasource.url=jdbc:postgresql://localhost:5432/tasks
spring.datasource.username=admin
spring.jpa.show-sql=true
spring.jpa.hibernate.ddl-auto=update
app.allowed-origins[0]=http://localhost:3000
app.allowed-origins[1]=http://localhost:8080
```

YAML

```
# application.yml — иерархический формат
server:
  port: 8080
spring:
  application:
    name: task-service
  datasource:
    url: jdbc:postgresql://localhost:5432/tasks
    username: admin
  jpa:
    show-sql: true
    hibernate:
      ddl-auto: update
app:
  allowed-origins:
    - http://localhost:3000
    - http://localhost:8080
```

Одна и та же информация. Разница — в синтаксисе и читаемости при росте конфигурации.

|Критерий|.properties|.yml|
|---|---|---|
|Формат|Плоский `ключ=значение`|Иерархический (отступы 2 пробела)|
|Вложенность|Через точку (повторение префиксов)|Нативная, без повторений|
|Списки|`list[0]=a`, `list[1]=b`|`- a`, `- b`|
|Читаемость|Хуже при глубокой вложенности|Лучше|
|Ошибки синтаксиса|Редки|Табы вместо пробелов — частая ловушка|
|Рекомендация|Legacy / простые проекты|✅ Стандарт для новых проектов|

**Рекомендация:** для всех новых проектов используй YAML. В этой статье работаем только с YAML.

YAML

```
# ⛔ Частая ошибка — табуляция вместо пробелов
server:
	port: 8080   # ← TAB, не пробел → ScannerException при старте!

# ✅ Правильно — два пробела
server:
  port: 8080
```

> ⚠️ **Антипаттерн:** использовать оба файла одновременно. Если в проекте есть `application.properties` и `application.yml` — `.properties` имеет более высокий приоритет и молча перезапишет совпадающие ключи из `.yml`. Выбери один формат.

## 4. @Value — инъекция одиночных значений

> **Уровень: Junior**

`@Value` — самый простой способ получить значение из конфигурации в Spring-бине. Значение подставляется из `Environment` в момент создания бина.

### Базовые примеры

YAML

```
# application.yml
app:
  name: TaskManager
  version: 2.1.0
  max-retries: 5
  feature-enabled: true
  # Список через запятую — для инъекции через @Value
  allowed-origins: http://localhost:3000,http://localhost:8080
```

Java

```
package com.example.taskservice.config;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;
import java.util.List;

@Component
public class AppInfo {

    // 1. Базовый — строковое значение
    @Value("${app.name}")
    private String appName;                     // → "TaskManager"

    // 2. С дефолтным значением — если свойство не найдено, используется "1.0"
    @Value("${app.version:1.0}")
    private String version;                     // → "2.1.0" (из конфига)

    // 3. Числовой тип — Spring автоматически конвертирует String → int
    @Value("${server.port:8080}")
    private int port;                           // → 8080

    // 4. Список — значения через запятую разбиваются автоматически
    @Value("${app.allowed-origins}")
    private List<String> allowedOrigins;        // → [http://localhost:3000, ...]

    // 5. Предпочтительный способ — инъекция через конструктор,
    //    поле можно сделать final (immutable)
    private final String appNameFinal;

    public AppInfo(@Value("${app.name}") String appNameFinal) {
        this.appNameFinal = appNameFinal;
    }
}
```

### Что происходит при отсутствии свойства без default

Java

```
// ⛔ Опасный код — если app.api-key не задан, приложение не стартует
@Value("${app.api-key}")
private String apiKey;
```

text

```
APPLICATION FAILED TO START

Description:
  Could not resolve placeholder 'app.api-key' in value "${app.api-key}"

Action:
  Ensure that 'app.api-key' is set, or add a default: @Value("${app.api-key:default}")
```

Spring выбрасывает `IllegalArgumentException` **при старте** (не при вызове метода). Это fail-fast поведение — лучше узнать о проблеме сразу, а не через час работы в production.

Java

```
// ✅ Безопасные варианты
@Value("${app.api-key:}")           // пустая строка по умолчанию
private String apiKeyOptional;

@Value("${app.timeout:30s}")        // разумный дефолт
private String timeout;
```

> 💡 **Важно знать:** `@Value` работает только в Spring-бинах. В обычных Java-объектах, созданных через `new`, инъекция не произойдёт — поле останется `null`.

### SpEL-выражения в @Value

> **Уровень: Senior** _(Junior может пропустить этот подраздел)_

`@Value` поддерживает не только `${...}` (property placeholder), но и `#{...}` (Spring Expression Language). SpEL позволяет выполнять вычисления и условную логику прямо в аннотации:

Java

```
package com.example.taskservice.config;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

@Component
public class SpELExamples {

    // Умножение: app.cache.ttl = 10 (минут) → 600 (секунд)
    @Value("#{${app.cache.ttl:10} * 60}")
    private int cacheTtlSeconds;

    // Elvis-оператор (?:) — fallback если переменная окружения не задана
    @Value("#{systemEnvironment['HOME'] ?: '/tmp'}")
    private String homeDir;

    // Конкатенация двух свойств в одну строку
    @Value("${app.protocol:http}://${app.host:localhost}:${server.port:8080}")
    private String baseUrl;

    // Условный оператор: тип порта зависит от его значения
    @Value("#{${server.port:8080} > 1024 ? 'unprivileged' : 'privileged'}")
    private String portType;
}
```

> 💡 **Важно знать:** SpEL мощный, но при злоупотреблении — источник трудноотлаживаемых проблем. Предпочтительнее переносить сложную логику в `@ConfigurationProperties` (раздел 8).

## 5. Профили и profile-specific файлы

> **Уровень: Junior**

Профиль — именованный набор конфигураций. `application-{profile}.yml` загружается при активации профиля `{profile}`. Базовый `application.yml` загружается **всегда** и служит фундаментом — профильный файл дополняет и перезаписывает только нужные ключи.

### Структура файлов

text

```
src/main/resources/
├── application.yml           ← всегда загружается (база)
├── application-dev.yml       ← только при профиле "dev"
├── application-test.yml      ← только при профиле "test"
└── application-prod.yml      ← только при профиле "prod"
```

### application.yml — общая база

YAML

```

spring:
  application:
    name: task-service
  jpa:
    open-in-view: false          # антипаттерн — отключаем везде
    properties:
      hibernate:
        format_sql: true         # форматировать SQL в логах

server:
  port: 8080
  shutdown: graceful             # ждём завершения активных запросов при остановке

app:
  name: TaskManager
  max-retries: 3
  cache:
    enabled: true
    ttl: 3600s
  allowed-origins:
    - http://localhost:3000
  feature-flags:
    new-priority-algorithm: false  # по умолчанию выключено везде

logging:
  pattern:
    console: "%d{HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n"

Java

```

## 7. @Profile на бинах и компонентах

> **Уровень: Middle**

`@Profile` регистрирует бин в контексте Spring **только** при активном указанном профиле. Идеально, когда в разных окружениях нужны принципиально разные реализации.

### @Profile на @Bean — разные DataSource

Java

```
package com.example.taskservice.config;

import com.zaxxer.hikari.HikariConfig;
import com.zaxxer.hikari.HikariDataSource;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Profile;
import org.springframework.jdbc.datasource.embedded.EmbeddedDatabaseBuilder;
import org.springframework.jdbc.datasource.embedded.EmbeddedDatabaseType;

import javax.sql.DataSource;

@Configuration
public class DataSourceConfig {

    // Создаётся ТОЛЬКО в dev — H2 не требует отдельного сервера
    @Bean
    @Profile("dev")
    public DataSource devDataSource() {
        return new EmbeddedDatabaseBuilder()
            .setType(EmbeddedDatabaseType.H2)
            .setName("taskdb")
            .addScript("classpath:schema.sql")    // создаём таблицы
            .addScript("classpath:data-dev.sql")  // тестовые данные
            .build();
    }

    // Создаётся ТОЛЬКО в prod — реальный PostgreSQL с пулом соединений
    @Bean
    @Profile("prod")
    public DataSource prodDataSource(
            @Value("${spring.datasource.url}") String url,
            @Value("${spring.datasource.username}") String username,
            @Value("${spring.datasource.password}") String password) {

        HikariConfig config = new HikariConfig();
        config.setJdbcUrl(url);
        config.setUsername(username);
        config.setPassword(password);
        config.setMaximumPoolSize(50);
        return new HikariDataSource(config);
    }
}
```

### @Profile на @Component — наполнение тестовыми данными

Java

```
package com.example.taskservice.dev;

import com.example.taskservice.entity.Task;
import com.example.taskservice.entity.User;
import com.example.taskservice.repository.TaskRepository;
import com.example.taskservice.repository.UserRepository;
import jakarta.annotation.PostConstruct;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.context.annotation.Profile;
import org.springframework.stereotype.Component;
import java.time.LocalDate;
import java.util.List;

/**
 * Наполняет БД тестовыми данными при старте в dev-окружении.
 * В prod этот компонент просто НЕ СУЩЕСТВУЕТ в контексте Spring.
 * Без @Profile он запустился бы в prod и засорил бы реальную БД!
 */
@Component
@Profile("dev")  // ← критически важно! Без этого компонент регистрируется ВСЕГДА
@RequiredArgsConstructor
@Slf4j
public class DevDataInitializer {

    private final UserRepository userRepository;
    private final TaskRepository taskRepository;

    @PostConstruct
    public void initDevData() {
        if (userRepository.count() > 0) {
            log.info("Dev data already exists, skipping");
            return;
        }
        log.info("Initializing development test data...");

        User alice = userRepository.save(User.builder()
            .username("alice")
            .email("alice@example.com")
            .build());

        taskRepository.saveAll(List.of(
            Task.builder()
                .title("Настроить CI/CD pipeline")
                .assignee(alice)
                .dueDate(LocalDate.now().plusDays(7))
                .build(),
            Task.builder()
                .title("Code review PR #42")
                .assignee(alice)
                .dueDate(LocalDate.now().plusDays(1))
                .build()
        ));

        log.info("Dev data: {} users, {} tasks",
            userRepository.count(), taskRepository.count());
    }
}
```

### Логические выражения в @Profile

Java

```
// OR — dev ИЛИ staging
@Component
@Profile("dev | staging")
public class VerboseAuditLogger { }

// NOT — все профили КРОМЕ test
@Component
@Profile("!test")
public class ExternalApiClient { }

// AND + NOT — prod без режима отладки
@Configuration
@Profile("prod & !debug")
public class StrictSecurityConfig { }
```

> 💡 **Важно знать:** Если бин не аннотирован `@Profile` — он регистрируется в контексте **при любом активном профиле**. Забытый `@Profile("dev")` на `DevDataInitializer` — реальная ошибка, которая запишет тестовые данные в production.

## 8. @ConfigurationProperties — типобезопасная конфигурация

> **Уровень: Middle**

Когда кастомных свойств становится больше пяти — `@Value` превращается в беспорядок: разрозненные поля в разных классах, нет IDE-поддержки, нет валидации. `@ConfigurationProperties` группирует связанные свойства в типизированный Java-объект.

> 🎯 **Если вы на уровне Junior** — освойте этот раздел полностью. Это основной инструмент для кастомной конфигурации в production-проектах.

### Схема потока данных

text

```
application.yml / ENV vars / CLI args
              ↓
         Environment
     (агрегатор всех источников)
              ↓
  ConfigurationPropertiesBindingPostProcessor
              ↓
       AppProperties (POJO / Record)
              ↓
  TaskService / SecurityService / etc.
```

### YAML-конфигурация для проекта

YAML

```
# application.yml — кастомные свойства приложения (добавляем к существующим)
app:
  name: TaskManager
  max-retries: 3
  allowed-origins:               # для CORS (пригодится в статье 6.14)
    - http://localhost:3000
    - https://taskmanager.example.com

  security:
    jwt-secret: ${JWT_SECRET}    # из переменной окружения — обязательно!
    token-expiration: 24h        # Duration: 24 часа

  cache:
    enabled: true
    ttl: 30m                     # Duration: 30 минут

  feature-flags:
    new-priority-algorithm: false  # включим в prod через application-prod.yml
    beta-api: false
```

### Класс AppProperties

Java

```
package com.example.taskservice.config;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.context.properties.NestedConfigurationProperty;

import java.time.Duration;
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * Типобезопасная конфигурация приложения.
 * Все свойства с префиксом "app" автоматически привязываются к полям.
 * prefix ДОЛЖЕН быть в lowercase kebab-case.
 */
@ConfigurationProperties(prefix = "app")
public class AppProperties {

    /** Отображаемое имя приложения */
    private String name;

    /** Максимальное количество повторных попыток при ошибке */
    private int maxRetries = 3;

    /** Разрешённые CORS origins (для Spring Security в статье 6.14) */
    private List<String> allowedOrigins = new ArrayList<>();

    /** Feature flags — включение фич без перезапуска */
    private Map<String, Boolean> featureFlags = new HashMap<>();

    /** Настройки безопасности и JWT */
    @NestedConfigurationProperty
    private Security security = new Security();

    /** Настройки кэширования */
    @NestedConfigurationProperty
    private Cache cache = new Cache();

    // ─── Вложенные классы ─────────────────────────────────────────────

    public static class Security {
        /** Секретный ключ для подписи JWT-токенов */
        private String jwtSecret;

        /**
         * Время жизни токена.
         * Spring Boot автоматически конвертирует строку в Duration:
         * "24h" → Duration.ofHours(24)
         * Поддерживаемые форматы: "30s", "5m", "2h", "1d", "PT30M" (ISO-8601)
         */
        private Duration tokenExpiration = Duration.ofHours(24);

        public String getJwtSecret() { return jwtSecret; }
        public void setJwtSecret(String v) { this.jwtSecret = v; }
        public Duration getTokenExpiration() { return tokenExpiration; }
        public void setTokenExpiration(Duration v) { this.tokenExpiration = v; }
    }

    public static class Cache {
        /** Включён ли кэш. Управляется через @ConditionalOnProperty */
        private boolean enabled = true;

        /**
         * Время жизни записи в кэше.
         * Форматы: "30m", "1h", "24h"
         */
        private Duration ttl = Duration.ofMinutes(30);

        public boolean isEnabled() { return enabled; }
        public void setEnabled(boolean v) { this.enabled = v; }
        public Duration getTtl() { return ttl; }
        public void setTtl(Duration v) { this.ttl = v; }
    }

    // ─── Getters/Setters для корневых полей ───────────────────────────
    // Обязательны для JavaBean binding!

    public String getName() { return name; }
    public void setName(String v) { this.name = v; }
    public int getMaxRetries() { return maxRetries; }
    public void setMaxRetries(int v) { this.maxRetries = v; }
    public List<String> getAllowedOrigins() { return allowedOrigins; }
    public void setAllowedOrigins(List<String> v) { this.allowedOrigins = v; }
    public Map<String, Boolean> getFeatureFlags() { return featureFlags; }
    public void setFeatureFlags(Map<String, Boolean> v) { this.featureFlags = v; }
    public Security getSecurity() { return security; }
    public void setSecurity(Security v) { this.security = v; }
    public Cache getCache() { return cache; }
    public void setCache(Cache v) { this.cache = v; }
}
```

> ⚠️ **Антипаттерн:** создать `@ConfigurationProperties`-класс и забыть его зарегистрировать. Класс есть, бина нет → `NoSuchBeanDefinitionException` при инъекции в другой компонент.

### Использование в сервисе

Java

```
package com.example.taskservice.service;

import com.example.taskservice.config.AppProperties;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
@Slf4j
public class TaskService {

    private final AppProperties appProperties; // инъекция как обычный бин

    public void processTask(Long taskId) {
        // Feature flag — без захардкоженных строк
        boolean useNewAlgorithm = appProperties.getFeatureFlags()
            .getOrDefault("new-priority-algorithm", false);

        if (useNewAlgorithm) {
            log.info("Используем новый алгоритм для задачи {}", taskId);
            processWithNewAlgorithm(taskId);
        } else {
            processWithLegacyAlgorithm(taskId);
        }
    }

    public long getTokenExpirationSeconds() {
        // Duration — типизированный, не просто число секунд
        return appProperties.getSecurity()
            .getTokenExpiration()
            .toSeconds();               // → 86400
    }

    private void processWithNewAlgorithm(Long id) { /* ... */ }
    private void processWithLegacyAlgorithm(Long id) { /* ... */ }
}
```

🔬 **Под капотом:** `ConfigurationPropertiesBindingPostProcessor` запускается при старте контекста. Он находит все бины с `@ConfigurationProperties`, читает свойства из `Environment` и привязывает их через рефлексию по JavaBean-конвенции (геттеры + сеттеры). Именно поэтому сеттеры обязательны при стандартном JavaBean-binding.

## 9. @ConfigurationProperties vs @Value

> **Уровень: Middle**

|Критерий|`@Value`|`@ConfigurationProperties`|
|---|---|---|
|Типобезопасность|❌ Строки, ручная конвертация|✅ Полноценные Java-типы|
|Вложенные объекты|❌ Только плоские значения|✅ Inner classes, records|
|Списки и Map|⚠️ `"a,b,c"` через split|✅ `List<T>`, `Map<K,V>` нативно|
|Duration / DataSize|❌ Ручная конвертация|✅ `"30m"` → `Duration` автоматически|
|Валидация|❌ Нет|✅ `@Validated` + Jakarta Bean Validation|
|IDE-автодополнение|❌ Нет metadata|✅ Через configuration-processor|
|Relaxed Binding|⚠️ Частичная|✅ Полная (`max-retries` = `MAX_RETRIES`)|
|SpEL выражения|✅ `#{expression}`|❌ Не поддерживает|
|Immutable|✅ `final` через конструктор|✅ Records / `@ConstructorBinding`|
|Когда использовать|1–2 простых значения или SpEL|Группа из 3+ связанных свойств|

Java

```
// ✅ @Value — уместно для одного-двух значений
@Value("${server.port:8080}")
private int port;

// ⛔ @Value — плохой выбор для группы связанных свойств
@Value("${app.security.jwt-secret}")
private String jwtSecret;
@Value("${app.security.token-expiration:86400}")
private int tokenExpSeconds;        // теряем Duration!
@Value("${app.security.refresh-expiration:604800}")
private int refreshExpSeconds;
// 10+ полей одного домена → пора переходить на @ConfigurationProperties

// ✅ @ConfigurationProperties — правильный выбор для группы
@ConfigurationProperties(prefix = "app.security")
public class SecurityProperties {
    private String jwtSecret;
    private Duration tokenExpiration;          // Duration нативно!
    private Duration refreshTokenExpiration;
}
```

## 10. @ConstructorBinding — Immutable конфигурация

> **Уровень: Middle/Senior**

JavaBean-binding требует сеттеров — любой код может изменить конфигурацию после создания бина. Для production-кода это нежелательно. Records и `@ConstructorBinding` делают конфигурацию неизменяемой.

### Immutable через Java Record (Spring Boot 3.x — рекомендуется)

Java

```
package com.example.taskservice.config;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.context.properties.bind.DefaultValue;
import org.springframework.validation.annotation.Validated;

import jakarta.validation.Valid;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotEmpty;

import java.time.Duration;
import java.util.List;
import java.util.Map;

/**
 * Immutable конфигурация через Java Record.
 *
 * В Spring Boot 3.x @ConstructorBinding НЕ НУЖНА если:
 * — класс является record (один канонический конструктор → автоматически)
 * — у обычного класса тоже ровно один конструктор
 *
 * @ConstructorBinding нужна ТОЛЬКО если у класса несколько конструкторов
 * и нужно явно указать Spring, какой из них использовать для binding.
 */
@ConfigurationProperties(prefix = "app")
@Validated
public record AppProperties(

    @NotBlank(message = "app.name обязателен")
    String name,

    @DefaultValue("3")
    @Min(1)
    int maxRetries,

    @NotEmpty(message = "Укажите хотя бы один allowed-origin")
    List<String> allowedOrigins,

    @DefaultValue Map<String, Boolean> featureFlags,

    @Valid @DefaultValue Security security,
    @Valid @DefaultValue Cache cache

) {
    /** Вложенный record — тоже immutable, только геттеры */
    public record Security(
        @NotBlank(message = "JWT secret обязателен. Установите JWT_SECRET env var")
        String jwtSecret,

        @DefaultValue("24h")
        Duration tokenExpiration
    ) {}

    public record Cache(
        @DefaultValue("true") boolean enabled,
        @DefaultValue("30m") Duration ttl
    ) {}
}
```

> 💡 **Важно знать:** В **Spring Boot 3.x** `@ConstructorBinding` ставится **на конструктор** (не на класс), и только если конструкторов несколько. При одном конструкторе или при использовании record — она избыточна и может быть опущена.

**Преимущество immutability:** конфигурация читается один раз при старте и больше никогда не меняется. Это исключает целый класс ошибок — случайное изменение конфигурации в runtime.

## 11. Валидация конфигурации при старте

> **Уровень: Middle/Senior**

Fail-fast принцип: лучше узнать о неверной конфигурации при старте, чем получить `NullPointerException` через два часа работы в production.

XML

```
<!-- pom.xml — требуется для @Validated на @ConfigurationProperties -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

Java

```
package com.example.taskservice.config;

import jakarta.validation.Valid;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotEmpty;
import jakarta.validation.constraints.NotNull;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.validation.annotation.Validated;

import java.time.Duration;
import java.util.List;
import java.util.Map;

// jakarta.validation — не javax.validation! (Spring Boot 3.x = Jakarta EE 9+)
@ConfigurationProperties(prefix = "app")
@Validated  // ← на классе, не на полях! Включает JSR-380 валидацию при старте
public class AppProperties {

    @NotBlank(message = "app.name обязателен")
    private String name;

    @Min(value = 1, message = "app.max-retries: минимум 1")
    @Max(value = 10, message = "app.max-retries: максимум 10")
    private int maxRetries = 3;

    @NotEmpty(message = "app.allowed-origins: укажите хотя бы один origin")
    private List<String> allowedOrigins;

    private Map<String, Boolean> featureFlags;

    @Valid      // ← каскадная валидация вложенного объекта
    @NotNull
    private Security security = new Security();

    @Valid
    @NotNull
    private Cache cache = new Cache();

    public static class Security {

        @NotBlank(message = "app.security.jwt-secret обязателен. " +
                             "Установите переменную окружения JWT_SECRET")
        private String jwtSecret;

        @NotNull
        private Duration tokenExpiration = Duration.ofHours(24);

        public String getJwtSecret() { return jwtSecret; }
        public void setJwtSecret(String v) { this.jwtSecret = v; }
        public Duration getTokenExpiration() { return tokenExpiration; }
        public void setTokenExpiration(Duration v) { this.tokenExpiration = v; }
    }

    public static class Cache {
        private boolean enabled = true;

        @NotNull
        private Duration ttl = Duration.ofMinutes(30);

        public boolean isEnabled() { return enabled; }
        public void setEnabled(boolean v) { this.enabled = v; }
        public Duration getTtl() { return ttl; }
        public void setTtl(Duration v) { this.ttl = v; }
    }

    public String getName() { return name; }
    public void setName(String v) { this.name = v; }
    public int getMaxRetries() { return maxRetries; }
    public void setMaxRetries(int v) { this.maxRetries = v; }
    public List<String> getAllowedOrigins() { return allowedOrigins; }
    public void setAllowedOrigins(List<String> v) { this.allowedOrigins = v; }
    public Map<String, Boolean> getFeatureFlags() { return featureFlags; }
    public void setFeatureFlags(Map<String, Boolean> v) { this.featureFlags = v; }
    public Security getSecurity() { return security; }
    public void setSecurity(Security v) { this.security = v; }
    public Cache getCache() { return cache; }
    public void setCache(Cache v) { this.cache = v; }
}
```

## 12. @ConditionalOnProperty — условная загрузка бинов

> **Уровень: Senior**

`@Profile` переключает окружение целиком. `@ConditionalOnProperty` управляет отдельным бином через значение конкретного свойства — независимо от профиля.

Java

```
package com.example.taskservice.config;

import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.cache.CacheManager;
import org.springframework.cache.concurrent.ConcurrentMapCacheManager;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class CacheConfig {

    /**
     * CacheManager создаётся ТОЛЬКО если app.cache.enabled=true.
     * Если свойство "false" или отсутствует — бин не создаётся,
     * кэширование через @Cacheable работать не будет.
     *
     * matchIfMissing=false (дефолт):
     *   — не создавать бин если свойство не задано вообще
     * matchIfMissing=true:
     *   — создавать бин если свойство отсутствует (opt-out паттерн)
     */
    @Bean
    @ConditionalOnProperty(
        name = "app.cache.enabled",
        havingValue = "true",
        matchIfMissing = false
    )
    public CacheManager cacheManager() {
        return new ConcurrentMapCacheManager("tasks", "users");
    }
}
```

Java

```
package com.example.taskservice.service;

import lombok.extern.slf4j.Slf4j;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.stereotype.Component;

/**
 * Новый алгоритм приоритизации задач — включается через feature flag.
 * Включить в production: app.feature-flags.new-priority-algorithm=true
 * Откатить: изменить на false и перезапустить. Без перекомпиляции!
 */
@Component
@ConditionalOnProperty(
    name = "app.feature-flags.new-priority-algorithm",
    havingValue = "true",
    matchIfMissing = false  // явно: выключено пока не включено
)
@Slf4j
public class NewPriorityAlgorithm {

    public void process(Long taskId) {
        log.info("Новый алгоритм приоритизации для задачи {}", taskId);
        // новая логика
    }
}
```

**Разница `@Profile` vs `@ConditionalOnProperty`:**

text

```
@Profile("prod")
  → бин существует ТОЛЬКО в prod
  → нельзя включить в dev без смены профиля

@ConditionalOnProperty("app.feature.X=true")
  → независимо от активного профиля
  → можно включить в любом окружении, изменив одно свойство
  → идеально для feature flags и опциональных компонентов
```

## 13. Порядок приоритетов источников конфигурации

> **Уровень: Middle → Senior**

### Базовая модель (Middle — достаточно для большинства случаев)

text

```
┌─────────────────────────────────────────────────┐
│  ПРИОРИТЕТ (↑ выше = побеждает при конфликте)   │
├─────────────────────────────────────────────────┤
│  1. CLI args        --server.port=9090   ВЫСШИЙ │
│  2. Env Variables   SERVER_PORT=9090            │
│  3. Profile YAML    application-prod.yml        │
│  4. Base YAML       application.yml             │
│  5. Default values  в коде (= 8080)    НИЗШИЙ  │
└─────────────────────────────────────────────────┘
```

Практический пример:

Bash

```

export SERVER_PORT=9090

# → server.port = 9090 (env var побеждает YAML)

# Запускаем с CLI-аргументом:
java -jar task-service.jar --server.port=7777
# → server.port = 7777 (CLI побеждает env var и YAML)
```

### Полная иерархия (Senior)

|Приоритет|Источник|Пример|
|---|---|---|
|**1 (высший)**|CLI arguments|`--server.port=9090`|
|**2**|System Properties (JVM)|`-Dserver.port=9090`|
|**3**|`SPRING_APPLICATION_JSON`|inline JSON через env var|
|**4**|OS Environment Variables|`SERVER_PORT=9090`|
|**5**|Profile-specific YAML **вне JAR**|`./config/application-prod.yml`|
|**6**|Profile-specific YAML **внутри JAR**|`resources/application-prod.yml`|
|**7**|Base `application.yml` **вне JAR**|`./config/application.yml`|
|**8**|Base `application.yml` **внутри JAR**|`resources/application.yml`|
|**9**|`@PropertySource`|`@PropertySource("classpath:custom.properties")`|
|**10 (низший)**|Default values|`SpringApplication.setDefaultProperties(...)`|

**Порядок поиска файлов конфигурации:**

text

```
1. file:./config/          ← вне JAR, в папке config/
2. file:./config/*/        ← вне JAR, в подпапках config/
3. file:./                 ← вне JAR, рядом с JAR
4. classpath:/config/      ← внутри JAR, папка config/
5. classpath:/             ← внутри JAR, корень (стандартное расположение)
```

🔬 **Под капотом:** `Environment` — интерфейс, абстрагирующий доступ ко всем источникам конфигурации. Его реализация хранит упорядоченный список `PropertySource` объектов. При запросе свойства Spring перебирает список сверху вниз и возвращает первое найденное значение. `PropertySourcesPlaceholderConfigurer` обрабатывает `${...}` в `@Value`, используя тот же `Environment`.

## 14. Relaxed Binding — гибкость имён свойств

> **Уровень: Senior**

Одно и то же свойство можно записать в разных форматах — Spring автоматически их маппит:

|Формат|Пример|Где используется|
|---|---|---|
|**kebab-case**|`app.jwt-secret`|`.yml` / `.properties` ✅ рекомендуется|
|**camelCase**|`app.jwtSecret`|Java-код (поле)|
|**UPPER_SNAKE_CASE**|`APP_JWT_SECRET`|OS Environment Variables|
|**dot.notation**|`app.jwt.secret`|Вложенные в `.properties`|

Java

```
// Все форматы маппятся на одно поле
@ConfigurationProperties(prefix = "app")
public class AppProperties {
    private String jwtSecret; // ← получит значение из любого формата выше
}
```

text

```
Алгоритм преобразования env var → имя свойства:
────────────────────────────────────────────────────────
APP_JWT_SECRET          → app.jwt-secret
SPRING_DATASOURCE_URL   → spring.datasource.url
SPRING_JPA_SHOWSQL      → spring.jpa.show-sql
APP_CACHE_TTL           → app.cache.ttl
APP_ALLOWEDORIGINS_0    → app.allowed-origins[0]
```

> 💡 **Важно знать:** Relaxed Binding работает **только** в `@ConfigurationProperties`. В `@Value("${app.jwt-secret}")` нельзя использовать `${APP_JWT_SECRET}` — нужно точное совпадение имени свойства. Это ещё одна причина предпочитать `@ConfigurationProperties` для кастомных свойств.

## 15. spring-boot-configuration-processor

> **Уровень: Senior**

Без дополнительных настроек IntelliJ IDEA подсвечивает кастомные свойства в `application.yml` как "неизвестные". `spring-boot-configuration-processor` решает это: при компиляции он генерирует метаданные, которые IDE использует для автодополнения.

XML

```
<!-- pom.xml -->
<!-- optional=true — не попадёт в транзитивные зависимости конечного JAR -->
<!-- Версия наследуется автоматически от spring-boot-starter-parent -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-configuration-processor</artifactId>
    <optional>true</optional>
</dependency>
```

groovy

```
// build.gradle.kts — для Gradle используем annotationProcessor
dependencies {
    annotationProcessor("org.springframework.boot:spring-boot-configuration-processor")
}
```

После выполнения `mvn compile` (или Build в IDE) в `target/classes/META-INF/` появится файл `spring-configuration-metadata.json`. IntelliJ IDEA и VS Code подхватят его автоматически — появятся автодополнение, типы и описания свойств.

### Javadoc → метаданные → IDE

Java

```
@ConfigurationProperties(prefix = "app")
public class AppProperties {

    /**
     * Максимальное количество повторных попыток при временных ошибках.
     * Увеличение значения повышает устойчивость, но замедляет ответ при сбоях.
     * Допустимый диапазон: 1–10. Default: 3.
     */
    @Min(1) @Max(10)
    private int maxRetries = 3;

    /**
     * Разрешённые CORS origins.
     * В production указывайте только домены вашего фронтенда.
     * Пример: https://taskmanager.example.com
     */
    @NotEmpty
    private List<String> allowedOrigins;
}
```

Javadoc-комментарии попадут в метаданные и будут отображаться в IDE как всплывающие подсказки при редактировании `application.yml`.

### Ручное добавление метаданных

Для свойств без `@ConfigurationProperties`-класса создайте файл:

JSON

```
// src/main/resources/META-INF/additional-spring-configuration-metadata.json
{
  "properties": [
    {
      "name": "app.feature-flags.new-priority-algorithm",
      "type": "java.lang.Boolean",
      "description": "Включает новый алгоритм приоритизации задач. Default: false",
      "defaultValue": false
    }
  ]
}
```

## 16. Секреты и безопасность конфигурации

> **Уровень: Senior+**

### Что происходит, когда пароль попадает в Git

text

```
⛔ СЦЕНАРИЙ УТЕЧКИ — реальный и очень распространённый:

1. Разработчик случайно коммитит application-prod.yml с паролем
   git commit -m "fix: update db config"
              ↓
2. Пуш в репозиторий (GitHub / GitLab / Bitbucket)
              ↓
3. GitGuardian / GitHub Secret Scanning сканирует каждый коммит
              ↓
4. Через ~30 секунд: уведомление "Secret detected in commit abc123"
              ↓
5. Пароль УЖЕ СКОМПРОМЕТИРОВАН — даже если удалить в следующем коммите,
   в git history он останется навсегда:
   git log --all -p -- application-prod.yml  ← найдёт пароль в любой момент
              ↓
6. Единственный выход: НЕМЕДЛЕННО сменить пароль в БД

Стоимость инцидента: от часов до дней работы + репутационные риски
```

> ⚠️ **Антипаттерн:** хранить секреты в Git — это не просто "плохая практика". Это нарушение безопасности с реальными последствиями. Если пароль попал в Git — он уже считается скомпрометированным.

```

  security:
    jwt-secret: my-jwt-key
```

### @DynamicPropertySource — Testcontainers

Java

```
package com.example.taskservice.repository;

import com.example.taskservice.entity.Task;
import com.example.taskservice.entity.User;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.orm.jpa.DataJpaTest;
import org.springframework.test.context.ActiveProfiles;
import org.springframework.test.context.DynamicPropertyRegistry;
import org.springframework.test.context.DynamicPropertySource;
import org.testcontainers.containers.PostgreSQLContainer;
import org.testcontainers.junit.jupiter.Container;
import org.testcontainers.junit.jupiter.Testcontainers;

import java.util.Optional;

import static org.assertj.core.api.Assertions.assertThat;

@DataJpaTest
@Testcontainers
@ActiveProfiles("test")
class TaskRepositoryIntegrationTest {

    @Container
    static PostgreSQLContainer<?> postgres =
        new PostgreSQLContainer<>("postgres:16-alpine")
            .withDatabaseName("taskdb_test")
            .withUsername("test_user")
            .withPassword("test_pass");

    /**
     * Вызывается ПОСЛЕ старта контейнера, ДО создания Spring-контекста.
     * Порт PostgreSQL назначается динамически — заранее неизвестен.
     * Именно для этого нужен @DynamicPropertySource.
     *
     * Сигнатура обязательна:
     * — static (метод вызывается до создания экземпляра тест-класса)
     * — void
     * — единственный параметр DynamicPropertyRegistry
     */
    @DynamicPropertySource
    static void configurePostgres(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
        registry.add("spring.datasource.password", postgres::getPassword);
        registry.add("spring.jpa.database-platform",
            () -> "org.hibernate.dialect.PostgreSQLDialect");
    }

    @Autowired
    private TaskRepository taskRepository;

    @Autowired
    private UserRepository userRepository;

    @Test
    void shouldSaveAndFindTask() {
        User user = userRepository.save(User.builder()
            .username("testuser")
            .email("test@example.com")
            .build());

        Task task = taskRepository.save(Task.builder()
            .title("Test task for integration test")
            .assignee(user)
            .build());

        Optional<Task> found = taskRepository.findById(task.getId());

        assertThat(found)
            .isPresent()
            .get()
            .extracting(Task::getTitle)
            .isEqualTo("Test task for integration test");
    }
}

```
package com.example.taskservice.config;

import org.junit.jupiter.api.Test;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.boot.context.properties.bind.BindValidationException;
import org.springframework.boot.test.context.runner.ApplicationContextRunner;
import org.springframework.context.annotation.Configuration;

import java.time.Duration;

import static org.assertj.core.api.Assertions.assertThat;

class AppPropertiesTest {

    // Лёгкий контекст без полного Spring Boot — быстрые изолированные тесты
    private final ApplicationContextRunner contextRunner =
        new ApplicationContextRunner()
            .withUserConfiguration(TestConfig.class);

    @Configuration
    @EnableConfigurationProperties(AppProperties.class)
    static class TestConfig { }

    @Test
    void shouldBindAllProperties() {
        contextRunner
            .withPropertyValues(
                "app.name=TestTaskManager",
                "app.max-retries=7",
                "app.allowed-origins=http://localhost:3000",
                "app.security.jwt-secret=test-secret-min-32-chars-long-enough",
                "app.security.token-expiration=12h",
                "app.cache.enabled=true",
                "app.cache.ttl=15m"
            )
            .run(context -> {
                assertThat(context).hasSingleBean(AppProperties.class);
                AppProperties props = context.getBean(AppProperties.class);

                assertThat(props.getName()).isEqualTo("TestTaskManager");
                assertThat(props.getMaxRetries()).isEqualTo(7);
                assertThat(props.getSecurity().getTokenExpiration())
                    .isEqualTo(Duration.ofHours(12));
                assertThat(props.getCache().getTtl())
                    .isEqualTo(Duration.ofMinutes(15));
            });
    }

    @Test
    void shouldFailValidationWhenJwtSecretBlank() {
        contextRunner
            .withPropertyValues(
                "app.name=TestApp",
                "app.allowed-origins=http://localhost:3000",
                "app.security.jwt-secret="  // пустой → нарушает @NotBlank
            )
            .run(context -> {
                assertThat(context).hasFailed();
                assertThat(context.getStartupFailure())
                    .rootCause()
                    .isInstanceOf(BindValidationException.class);
            });
    }

    @Test
    void shouldUseDefaultValues() {
        contextRunner
            .withPropertyValues(
                "app.name=MinimalApp",
                "app.allowed-origins=http://localhost:3000",
                "app.security.jwt-secret=test-secret-min-32-chars-long-enough"
            )
            .run(context -> {
                AppProperties props = context.getBean(AppProperties.class);
                assertThat(props.getMaxRetries()).isEqualTo(3);          // default
                assertThat(props.getCache().isEnabled()).isTrue();       // default
                assertThat(props.getCache().getTtl())
                    .isEqualTo(Duration.ofMinutes(30));                  // default
            });
    }
}

@ConfigurationProperties(prefix = "game")
@Validated
public class GameProperties {

    //   maxLevel: int, @Min(1) @Max(1000)

    // Геттеры и сеттеры для всех полей

## 19. Итоги

### Что мы изучили

В этой статье мы прошли путь от единого `application.properties` до профессиональной конфигурации production-ready приложения:

|Инструмент|Уровень|Для чего|
|---|---|---|
|`application.yml`|Intern|Базовый формат конфигурации|
|`application-{profile}.yml`|Junior|Конфигурация по окружениям|
|`@Value`|Junior|Инъекция одиночных значений|
|`@Profile`|Middle|Условные бины по окружению|
|`@ConfigurationProperties`|Middle|Типобезопасная группа свойств|
|`@Validated`|Middle|Fail-fast валидация при старте|
|`@ConstructorBinding` / Record|Senior|Immutable конфигурация|
|`@ConditionalOnProperty`|Senior|Feature flags, условные бины|
|Приоритеты источников|Senior|Отладка конфигурации|
|Secrets Management|Senior+|Безопасность production|

### Сводная таблица аннотаций

|Аннотация|Назначение|Где ставить|
|---|---|---|
|`@Value`|Инъекция одного свойства / SpEL|Поле, параметр конструктора|
|`@Profile`|Условная регистрация по профилю|`@Component`, `@Bean`, `@Configuration`|
|`@ConfigurationProperties`|Типобезопасная группа свойств|Класс / record|
|`@EnableConfigurationProperties`|Регистрация класса|`@SpringBootApplication` / `@Configuration`|
|`@ConfigurationPropertiesScan`|Авто-сканирование пакета|`@SpringBootApplication`|
|`@ConstructorBinding`|Constructor binding при нескольких конструкторах|Конструктор класса|
|`@Validated`|Включает JSR-380 валидацию при старте|`@ConfigurationProperties` класс|
|`@NestedConfigurationProperty`|Подсказка IDE-процессору о вложенном объекте|Поле класса|
|`@ConditionalOnProperty`|Создание бина по значению свойства|`@Bean`, `@Configuration`, `@Component`|
|`@ActiveProfiles`|Активация профилей в тестах|Тестовый класс|
|`@TestPropertySource`|Переопределение свойств в тестах|Тестовый класс|
|`@DynamicPropertySource`|Динамическая регистрация свойств (Testcontainers)|`static` метод в тестовом классе|
