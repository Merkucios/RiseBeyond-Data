## 1. От Контекста к Вебу

> **[Уровень: Intern]**

В статьях 6.1–6.3 мы создавали бины, внедряли зависимости и запускали код из `main()`. Всё это происходило внутри приложения — никто снаружи не мог с ним взаимодействовать.

Теперь мы меняем это. **Контроллер** — это бин Spring (помните статью 6.3?), который:

1. Слушает входящие HTTP-запросы по определённому адресу
2. Вызывает нужную логику
3. Возвращает HTTP-ответ клиенту

Если раньше вы вызывали `userService.findAll()` из `main()`, теперь этот же метод будет вызываться автоматически, когда кто-то обратится к вашему API по адресу `GET /api/users`.

> **💡 Связь с предыдущими статьями**
> 
> `@RestController` включает в себя `@Component` (статья 6.3) — Spring автоматически создаёт экземпляр контроллера и регистрирует его как бин в контексте приложения. Зависимости (сервисы, репозитории) внедряются через конструктор — точно так же, как вы изучали в статье 6.1:
> 
> Java
> 
> ```
> @RestController
> public class TaskController {
>     private final TaskService taskService; // зависимость
> 
>     // Spring автоматически внедрит TaskService (DI из статьи 6.1)
>     public TaskController(TaskService taskService) {
>         this.taskService = taskService;
>     }
> }
> ```
> 
> В этой статье мы пока обходимся без сервисного слоя — добавим его в статье 6.5.

## 2. HTTP за 5 Минут

> **[Уровень: Intern]**

Прежде чем писать контроллер, нужно понять, что он обрабатывает.

**HTTP (HyperText Transfer Protocol)** — протокол общения клиента и сервера. Каждое взаимодействие состоит из двух частей:

text

```
ЗАПРОС (Request)                       ОТВЕТ (Response)
─────────────────────────────          ──────────────────────────────
POST /api/tasks HTTP/1.1               HTTP/1.1 201 Created
Host: localhost:8080                   Location: /api/tasks/1
Content-Type: application/json         Content-Type: application/json

{"title": "Изучить Spring"}            {"id":1,"title":"Изучить Spring"}

│                                      │
├─ Метод: POST  (что делаем)           ├─ Статус: 201 (результат)
├─ Путь: /api/tasks (куда)             ├─ Заголовки (метаданные ответа)
├─ Заголовки (метаданные запроса)      └─ Тело (данные ответа)
└─ Тело (данные запроса)
```

**Клиентом** может быть браузер, мобильное приложение, другой микросервис или утилита `curl`. Все они говорят с вашим API на одном языке — HTTP.

**Ключевые понятия:**

- **Метод** (GET, POST, PUT...) — что мы хотим сделать с ресурсом
- **Путь** (`/api/tasks`) — какой ресурс нас интересует
- **Заголовки** — метаданные: тип содержимого, авторизация и т.д.
- **Тело** — данные запроса или ответа (обычно JSON)
- **Статус-код** (200, 201, 404...) — результат выполнения запроса

### Шаг 1: Добавляем зависимость

Откройте `pom.xml` вашего проекта и добавьте зависимости **внутрь уже существующей секции** `<dependencies>` (она есть в любом Spring Boot проекте):

XML

```
<dependencies>
    <!-- ↓ Добавьте эти зависимости внутрь существующего тега <dependencies> ↓ -->

    <!-- Основной стартер для Web: Spring MVC + встроенный Tomcat + Jackson (JSON) -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

    <!-- Валидация входных данных (@Valid, @NotBlank и т.д.)
         Активно используется в статье 6.5, добавляем сейчас для удобства -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-validation</artifactId>
    </dependency>

    <!-- Тестирование: JUnit 5 + Mockito + MockMvc
         scope=test означает: зависимость только для тестов, не попадёт в production jar -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>
```

`spring-boot-starter-web` подтягивает три ключевых компонента:

|Компонент|Роль|
|---|---|
|**Spring MVC**|Фреймворк для обработки HTTP-запросов|
|**Embedded Tomcat**|Встроенный сервер — не нужно разворачивать `.war` файл|
|**Jackson**|Библиотека для конвертации Java-объектов в JSON и обратно|

## 4. Архитектура Spring MVC

> **[Уровень: Junior / Middle]**

### 4.1 Паттерн MVC

**MVC (Model-View-Controller)** — архитектурный паттерн, который разделяет приложение на три части с чёткими обязанностями.

Представьте ресторан:

text

```
┌──────────┐  заказ   ┌─────────────┐  задание  ┌──────────┐
│  КЛИЕНТ  │─────────►│   ОФИЦИАНТ  │──────────►│  КУХНЯ   │
│(Browser) │          │ (Controller)│           │  (Model) │
│          │◄─────────│             │◄──────────│  данные  │
└──────────┘  ответ   └──────┬──────┘ результат └──────────┘
                             │ передаёт данные
                      ┌──────▼──────┐
                      │  СЕРВИРОВКА │
                      │   (View)    │
                      │ HTML / JSON │
                      └─────────────┘

Model      — данные и бизнес-логика (сущности, сервисы, репозитории)
View       — представление: HTML-страница или JSON-ответ
Controller — посредник: принимает запрос, обращается к Model, возвращает View
```

В REST API роль **View** минимальна: Jackson просто сериализует Java-объект в JSON — как официант упаковывает блюдо в контейнер. Основная работа происходит в Model (бизнес-логика) и Controller (маршрутизация запросов).

### 4.2 DispatcherServlet — Главный Дирижёр

**Front Controller Pattern** — все входящие запросы проходят через одну точку входа, которая распределяет их нужным обработчикам.

**Аналогия:** стойка ресепшн в большом отеле. Все гости (HTTP-запросы) сначала обращаются к администратору (DispatcherServlet). Администратор смотрит в **книгу маршрутов** (HandlerMapping): `"GET /spa" → СПА-отдел`, `"GET /restaurant" → Ресторан`, `"GET /unknown" → "Извините, такого нет" (404)`. Найдя нужный отдел, звонит туда (HandlerAdapter вызывает метод контроллера). Отдел выполняет работу и передаёт результат обратно через администратора. Гость никогда не ходит в отделы напрямую — только через ресепшн.

Вот полная схема прохождения запроса:

text

```
  Браузер / curl / Postman
         │
         │  HTTP Request: GET /api/tasks/1
         ▼
┌────────────────────────────────────────────────────────────────┐
│                     DispatcherServlet                          │
│   Единая точка входа (Front Controller).                       │
│   Получает ВСЕ запросы, оркестрирует всю обработку.           │
└──────┬──────────────────────────────────────────────┬──────────┘
       │ 1. Кто обработает?                           │ 6. Записать ответ
       ▼                                              │
┌──────────────────┐                                  │
│  HandlerMapping  │                                  │
│  (Книга маршрутов│                                  │
│  Ищет контроллер │                                  │
│  по URL + методу)│                                  │
│                  │                                  │
│  GET /tasks/{id} │                                  │
│  → TaskController│                                  │
└──────┬───────────┘                                  │
       │ 2. Вызвать метод                             │
       ▼                                              │
┌──────────────────┐   3. Выполнить   ┌───────────────┴──┐
│  HandlerAdapter  │─────────────────►│    Controller    │
│  (Разрешает      │                  │  getTaskById()   │
│  аргументы:      │◄─────────────────│  @PathVariable   │
│  @PathVariable,  │   4. Результат   │  Long id → 1L    │
│  @RequestBody...)│   TaskResponse   └──────────────────┘
└──────┬───────────┘
       │ 5. Конвертировать в HTTP-ответ
       ▼
┌────────────────────────────────────────────────────────────────┐
│            HttpMessageConverter (Jackson)                      │
│                                                                │
│  @RestController → ObjectMapper сериализует объект в JSON     │
│  @Controller     → ViewResolver ищет HTML-шаблон по имени     │
└──────────────────────────────────┬─────────────────────────────┘
                                   │
                                   ▼
                        HTTP Response: 200 OK
                        Content-Type: application/json
                        {"id":1,"title":"...","done":false}
```

> **🔬 Под капотом (Senior)**
> 
> `HandlerMapping` в Spring Boot — это `RequestMappingHandlerMapping`. При старте приложения он сканирует все бины с `@Controller`/`@RestController` и строит внутреннюю карту: `(HTTP метод + URL паттерн) → метод контроллера`. Именно поэтому при старте в логах видно: `Mapped "{[/api/tasks],methods=[GET]}"`.
> 
> `HandlerAdapter` (конкретно `RequestMappingHandlerAdapter`) отвечает за **разрешение аргументов**: видит параметр `@PathVariable Long id`, извлекает строку `"1"` из URL и конвертирует её в `Long` через встроенный `ConversionService`.
> 
> `HttpMessageConverter` — интерфейс, реализация `MappingJackson2HttpMessageConverter` смотрит на заголовок `Accept` запроса (обычно `application/json`) и вызывает `ObjectMapper.writeValueAsString(result)`.
> 
> В Spring Boot `DispatcherServlet` регистрируется **автоматически** через `DispatcherServletAutoConfiguration` — вам не нужно писать ни строчки конфигурации.

## 5. Первый Контроллер: Hello World

> **[Уровень: Intern]**

Создайте файл `HelloController.java` в пакете `controller` (правая кнопка на пакете → New → Java Class):

Java

```
package com.example.taskmanager.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.Map;

// @RestController = @Controller + @ResponseBody на каждом методе
// Также включает @Component → Spring создаёт бин автоматически (статья 6.3)
@RestController
// @RequestMapping задаёт базовый путь: все методы класса доступны по /api/hello/...
@RequestMapping("/api/hello")
public class HelloController {

    // GET /api/hello → возвращает строку в теле ответа
    @GetMapping
    public String hello() {
        return "Привет, Spring Web!";
    }

    // GET /api/hello/info → возвращает объект (Jackson сериализует в JSON)
    @GetMapping("/info")
    public Map<String, String> info() {
        // Важно: Map.of() создаёт неизменяемую карту.
        // Порядок полей в JSON не гарантирован — это нормально для Map.
        return Map.of(
            "framework", "Spring Boot",
            "version",   "3.x",
            "status",    "running"
        );
    }
}
```

```

```

  "version": "3.x",
  "status": "running"
}
```

> **💡 Порядок полей в JSON**
> 
> При использовании `Map.of()` порядок полей в JSON **не гарантирован** — HashMap не хранит порядок вставки. Ваш ответ может выглядеть так: `{"status":"running","framework":"Spring Boot","version":"3.x"}`. Это абсолютно нормально. Если порядок важен, используйте `LinkedHashMap` или DTO-класс.

> `GET /api/hello/greet/Иван` → `"Привет, Иван!"`  
> Подсказка: используйте `@PathVariable` (разберём подробно в разделе 8.3).

## 6. @Controller vs @RestController

> **[Уровень: Junior]**

Это различие критически важно — его непонимание приводит к одной из самых частых ошибок:

Java

```
package com.example.taskmanager.controller;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.ResponseBody;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;

// ═══ ВАРИАНТ 1: @Controller ══════════════════════════════════════════
// Используется для серверного рендеринга HTML (Thymeleaf, FreeMarker, JSP)
@Controller
public class WebPageController {

    // Возвращает ИМЯ ШАБЛОНА — Spring ищет файл templates/home.html
    // Если файла нет → ошибка "Template 'home' could not be found"
    @GetMapping("/home")
    public String showHomePage() {
        return "home"; // → src/main/resources/templates/home.html
    }

    // Чтобы вернуть данные (не шаблон) — нужен явный @ResponseBody
    @GetMapping("/api/ping")
    @ResponseBody
    public String ping() {
        return "pong"; // → строка "pong" в теле HTTP-ответа
    }
}

// ═══ ВАРИАНТ 2: @RestController ══════════════════════════════════════
// @RestController = @Controller + @ResponseBody на КАЖДОМ методе
// Используется для REST API — возвращает данные (JSON), не шаблоны
@RestController
public class TaskApiController {

    // @ResponseBody применяется автоматически — Jackson сериализует в JSON
    @GetMapping("/api/tasks")
    public List<String> getTasks() {
        return List.of("Задача 1", "Задача 2");
    }
}
```

**Правило выбора:**

|Ситуация|Аннотация|
|---|---|
|Строите REST API (JSON-ответы)|`@RestController`|
|Рендерите HTML на сервере (Thymeleaf)|`@Controller`|
|Смешанный контроллер: и HTML, и JSON|`@Controller` + `@ResponseBody` на нужных методах|

> **⚠️ Частая ошибка: забыли @ResponseBody**
> 
> Java
> 
> ```
> @Controller  // ← НЕ @RestController
> public class ApiController {
>     @GetMapping("/api/tasks")
>     public List<Task> getTasks() {
>         return List.of(new Task(1L, "Тест", false));
>     }
> }
> ```
> 
> Вы увидите в логах Spring:
> 
> text
> 
> ```
> javax.servlet.ServletException: Circular view path [tasks]:
> would dispatch back to the current handler URL [/api/tasks]
> -- или --
> Error resolving template [com.example.Task@3a4b5c],
> template might not exist or might not be accessible
> ```
> 
> Spring принимает возвращённый объект за **имя HTML-шаблона** и безуспешно его ищет.
> 
> **Решение:** замените `@Controller` на `@RestController`, или добавьте `@ResponseBody` на метод.

## 7. HTTP Методы и Маппинг

> **[Уровень: Junior]**

HTTP-протокол определяет методы (глаголы) с разной семантикой. Выбор правильного метода — признак хорошего REST API:

|Метод|Аннотация Spring|Семантика|Идемпотентность|Тело запроса|Типичный статус ответа|
|---|---|---|---|---|---|
|GET|`@GetMapping`|Получить ресурс|✅ Да|Нет|200 OK|
|POST|`@PostMapping`|Создать ресурс|❌ Нет|Да (JSON)|201 Created|
|PUT|`@PutMapping`|Полное обновление|✅ Да|Да (JSON)|200 OK|
|PATCH|`@PatchMapping`|Частичное обновление|❌ Нет|Да (JSON)|200 OK|
|DELETE|`@DeleteMapping`|Удалить ресурс|✅ Да|Нет|204 No Content|

> **💡 Что такое идемпотентность?**
> 
> Идемпотентный запрос можно выполнить **сколько угодно раз** — результат будет одинаковым. `DELETE /tasks/1` десять раз → задача всё равно удалена (эффект тот же, что и после первого вызова). `POST /tasks` десять раз → создано десять задач (каждый раз новый эффект). Это важно для надёжности распределённых систем: если клиент не получил ответ, он может безопасно повторить идемпотентный запрос.

Все аннотации — сокращения `@RequestMapping` с указанием метода:

Java

```
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestMethod;
import org.springframework.web.bind.annotation.RestController;

// Эти записи полностью эквивалентны:
@RequestMapping(value = "/tasks", method = RequestMethod.GET)
@GetMapping("/tasks")   // ← предпочтительная краткая форма

// @RequestMapping на уровне класса задаёт базовый путь для ВСЕХ методов —
// избавляет от дублирования "/api/tasks" в каждом методе:
@RestController
@RequestMapping("/api/tasks")  // базовый путь
public class TaskController {

    @GetMapping            // → GET    /api/tasks
    public Object getAll() { return null; }

    @GetMapping("/{id}")   // → GET    /api/tasks/{id}
    public Object getOne() { return null; }

    @PostMapping           // → POST   /api/tasks
    public Object create() { return null; }

    @PutMapping("/{id}")   // → PUT    /api/tasks/{id}
    public Object update() { return null; }

    @DeleteMapping("/{id}") // → DELETE /api/tasks/{id}
    public Object delete() { return null; }
}
```

> **💡 REST соглашения по именованию URL**
> 
> text
> 
> ```
> ✅ /api/tasks           — коллекция ресурсов (множественное число)
> ✅ /api/tasks/1         — конкретный ресурс (идентификатор)
> ✅ /api/tasks/1/comments — вложенные ресурсы
> 
> ❌ /api/getTask         — глагол в URL (нарушение REST, метод уже в HTTP-глаголе)
> ❌ /api/task            — единственное число для коллекции
> ❌ /api/Tasks           — заглавная буква
> ❌ /api/tasks/          — лишний слеш в конце
> ```

### 8.2 @RequestParam — Параметры строки запроса

Читает параметры из query string ("строки запроса") — части URL после знака `?`:

Java

```
package com.example.taskmanager.controller;

// Этот контроллер создан только для демонстрации @RequestParam.
// В финальный проект TaskController его добавлять не нужно.

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.util.Map;

@RestController
@RequestMapping("/api/demo")
public class ParamDemoController {

    // GET /api/demo/filter?status=active&done=true&limit=5
    @GetMapping("/filter")
    public Map<String, Object> filter(
            // Обязательный параметр: если не передан → HTTP 400 Bad Request
            @RequestParam String status,

            // Необязательный: если не передан → null (тип должен быть объектным, не примитивом)
            @RequestParam(required = false) Boolean done,

            // Со значением по умолчанию: если не передан → используется "10"
            @RequestParam(defaultValue = "10") int limit,

            // Кастомное имя параметра в URL: ?sort_by=title
            @RequestParam(name = "sort_by", defaultValue = "id") String sortBy
    ) {
        return Map.of(
            "status", status,
            "done",   done != null ? done : "не указано",
            "limit",  limit,
            "sortBy", sortBy
        );
    }
}
```

Bash

```
# Все параметры переданы
curl "http://localhost:8080/api/demo/filter?status=active&done=true&limit=5"

# Только обязательный параметр, остальные — значения по умолчанию
curl "http://localhost:8080/api/demo/filter?status=active"

# Без обязательного параметра → 400 Bad Request
curl "http://localhost:8080/api/demo/filter"
```

**Когда `@RequestParam`:** фильтрация, сортировка, пагинация — `?page=2&size=10&sort=name`

### 8.3 @PathVariable — Переменные пути

Читает значения прямо из URL-пути. Фигурные скобки в `@GetMapping("/{id}")` определяют шаблон:

Java

```
package com.example.taskmanager.controller;

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.Map;

@RestController
@RequestMapping("/api/demo")
public class PathDemoController {

    // GET /api/demo/users/42
    // {id} в URL → переменная id в методе
    @GetMapping("/users/{id}")
    public Map<String, Object> getUser(@PathVariable Long id) {
        return Map.of("userId", id, "message", "Пользователь найден");
    }

    // GET /api/demo/categories/5/products/123
    // Несколько переменных; имена в @PathVariable должны совпадать с именами в URL
    @GetMapping("/categories/{categoryId}/products/{productId}")
    public Map<String, Object> getProduct(
            @PathVariable Long categoryId,
            @PathVariable Long productId) {
        return Map.of("categoryId", categoryId, "productId", productId);
    }
}
```

Bash

```
# Получаем пользователя с ID = 42
curl http://localhost:8080/api/demo/users/42
```

JSON

```
{"userId": 42, "message": "Пользователь найден"}
```

**Когда `@PathVariable`:** идентификация конкретного ресурса — `/users/42`, `/orders/100`

> **💡 @PathVariable vs @RequestParam — итоговое правило**
> 
> |Что передаём|Как передаём|Аннотация|
> |---|---|---|
> |Идентификатор ресурса|`/tasks/42` (часть пути)|`@PathVariable`|
> |Фильтр, сортировка|`?done=true&limit=10` (после `?`)|`@RequestParam`|

### 8.4 @RequestBody — Тело запроса (JSON → Java)

Десериализует JSON из тела запроса в Java-объект. Jackson выполняет конвертацию автоматически:

Java

```

import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

// DTO для входящих данных.
// Record (Java 16+) — лаконичный неизменяемый класс данных.
// Jackson читает поля через аксессоры record: title(), done()
public record TaskRequest(String title, boolean done) {}

// Этот контроллер создан только для демонстрации @RequestBody.
@RestController
@RequestMapping("/api/demo")
public class BodyDemoController {

    // POST /api/demo/echo с телом {"title":"Test","done":false}
    @PostMapping("/echo")
    public TaskRequest echo(@RequestBody TaskRequest request) {
        // Jackson автоматически сериализует обратно в JSON
        return request;
    }
}
```

```

```

>

>

## 9. ResponseEntity и HTTP-статусы

> **[Уровень: Middle]**

### 9.1 Семантика HTTP-статусов

Возвращать всегда `200 OK` — распространённая ошибка. Статус-код сообщает клиенту, что именно произошло:

|Код|Название|Когда использовать|
|---|---|---|
|200|OK|Успешный GET, PUT, PATCH|
|201|Created|Ресурс создан (POST) — добавляйте заголовок `Location`|
|204|No Content|Успешно, но нечего возвращать (DELETE)|
|400|Bad Request|Ошибка валидации входных данных|
|404|Not Found|Ресурс не найден|
|409|Conflict|Конфликт (например, дублирование уникального поля)|
|500|Internal Server Error|Непредвиденная ошибка на сервере|

### 9.2 Простой возврат vs ResponseEntity

Java

```
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;

// ─── Простой возврат: статус всегда 200, нет контроля ──────────────
@GetMapping("/{id}")
public Task getTaskSimple(@PathVariable Long id) {
    return storage.get(id);
    // Если задачи нет → вернёт null → Jackson сериализует как пустое тело
    // Клиент получит 200 OK с пустым телом — нарушение REST-контракта!
}

// ─── ResponseEntity: полный контроль над ответом ────────────────────
@GetMapping("/{id}")
public ResponseEntity<Task> getTaskFull(@PathVariable Long id) {
    Task task = storage.get(id);
    if (task == null) {
        return ResponseEntity.notFound().build(); // 404 без тела
    }
    return ResponseEntity.ok(task); // 200 + JSON
}
```

### 9.3 Builder-методы ResponseEntity

Java

```
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import java.net.URI;

// 200 OK + тело ответа
ResponseEntity.ok(body)

// 201 Created + заголовок Location (стандарт REST: указывает URL нового ресурса)
ResponseEntity.created(URI.create("/api/tasks/" + id)).body(body)

// 204 No Content (тела нет — только статус)
ResponseEntity.noContent().build()

// 404 Not Found без тела
ResponseEntity.notFound().build()

// 400 Bad Request с описанием ошибки
ResponseEntity.badRequest().body("Поле title не может быть пустым")

// Произвольный статус + кастомные заголовки
ResponseEntity
    .status(HttpStatus.CONFLICT)
    .header("X-Error-Code", "DUPLICATE_TITLE")
    .body("Задача с таким названием уже существует")
```

### 9.4 @ResponseStatus — Декларативный статус

Когда статус метода **всегда одинаков**, можно объявить его аннотацией вместо `ResponseEntity`:

Java

```
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.ResponseStatus;

// Метод всегда возвращает 201 Created — не нужно оборачивать в ResponseEntity
@PostMapping
@ResponseStatus(HttpStatus.CREATED)
public TaskResponse createTask(@RequestBody TaskRequest request) {
    return taskService.create(request);
}

// void метод + 204 No Content (тело ответа не нужно)
@DeleteMapping("/{id}")
@ResponseStatus(HttpStatus.NO_CONTENT)
public void deleteTask(@PathVariable Long id) {
    taskService.delete(id);
}
```

> **💡 ResponseEntity vs @ResponseStatus — когда что?**
> 
> - `@ResponseStatus` — когда статус **всегда одинаков** (проще, декларативно). Также часто используется совместно с `@ExceptionHandler` для обработки исключений — разберём в статье 6.5.
> - `ResponseEntity` — когда статус **зависит от результата**: нашли ресурс → 200, не нашли → 404. Даёт полный контроль над заголовками и телом ответа.

## 10. Практика: Полный CRUD (Task Manager)

> **[Уровень: Middle]**

Собираем всё вместе. Реализуем REST API для управления задачами с хранением данных в памяти приложения.

### Шаг 1: Создаём модель Task

Создайте файл `Task.java` в пакете `model`:

Java

```
// src/main/java/com/example/taskmanager/model/Task.java
package com.example.taskmanager.model;

// Сущность задачи — внутренняя модель приложения.
// НЕ возвращаем её напрямую клиенту: используем DTO (TaskResponse).
public class Task {
    private Long id;
    private String title;
    private boolean done;

    public Task(Long id, String title, boolean done) {
        this.id = id;
        this.title = title;
        this.done = done;
    }

    // Геттеры ОБЯЗАТЕЛЬНЫ — Jackson читает поля через них при сериализации в JSON!
    public Long getId()      { return id; }
    public String getTitle() { return title; }
    public boolean isDone()  { return done; }

    // Сеттеры нужны для обновления полей при PUT/PATCH запросах
    public void setTitle(String title) { this.title = title; }
    public void setDone(boolean done)  { this.done = done; }
}
```

### Шаг 2: Создаём DTO-классы

Создайте файл `TaskRequest.java` в пакете `dto`:

Java

```
// src/main/java/com/example/taskmanager/dto/TaskRequest.java
package com.example.taskmanager.dto;

// DTO (Data Transfer Object) для входящих данных — создание и полное обновление задачи.
// Record: неизменяемый, лаконичный, Jackson-совместимый (Java 16+).
// Jackson десериализует JSON → record через конструктор и имена компонентов.
public record TaskRequest(
        String title,  // Заголовок задачи
        boolean done   // Статус выполнения
) {}
```

Создайте файл `TaskResponse.java` в пакете `dto`:

Java

```
// src/main/java/com/example/taskmanager/dto/TaskResponse.java
package com.example.taskmanager.dto;

// DTO для исходящих данных — то, что возвращаем клиенту.
// Отдельный класс защищает от случайной утечки внутренних полей модели.
public record TaskResponse(
        Long id,
        String title,
        boolean done
) {}
```

// src/main/java/com/example/taskmanager/dto/TaskPatchRequest.java
package com.example.taskmanager.dto;

// DTO для частичного обновления задачи (PATCH).
// Все поля — объектные типы (не примитивы), чтобы null означал "не передано".
// Boolean (не boolean): если клиент не передал поле → null → не обновляем.

### Шаг 3: Пишем контроллер TaskController

Создайте файл `TaskController.java` в пакете `controller`:

Java

```
// src/main/java/com/example/taskmanager/controller/TaskController.java
package com.example.taskmanager.controller;

import com.example.taskmanager.dto.TaskPatchRequest;
import com.example.taskmanager.dto.TaskRequest;
import com.example.taskmanager.dto.TaskResponse;
import com.example.taskmanager.model.Task;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PatchMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.net.URI;
import java.util.List;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicLong;
import java.util.stream.Collectors;

@RestController
@RequestMapping("/api/tasks")
public class TaskController {

    // ConcurrentHashMap — потокобезопасная реализация Map.
    // Tomcat обрабатывает каждый HTTP-запрос в отдельном потоке (thread).
    // Обычный HashMap при одновременном чтении и записи из разных потоков
    // может повредить внутреннюю структуру и привести к непредсказуемому поведению.
    // ConcurrentHashMap решает это через сегментированные блокировки.
    private final Map<Long, Task> storage = new ConcurrentHashMap<>();

    // AtomicLong — потокобезопасный счётчик для генерации уникальных ID.
    // Операция counter++ НЕ атомарна: это три шага (read, increment, write).
    // При конкурентном доступе два потока могут прочитать одно значение
    // и оба получат одинаковый ID. AtomicLong.getAndIncrement() — атомарная операция.
    private final AtomicLong idCounter = new AtomicLong(1);

    // ═══════════════════════════════════════════════════════════════════════
    // GET /api/tasks — Получить список всех задач
    // ═══════════════════════════════════════════════════════════════════════
    @GetMapping
    public ResponseEntity<List<TaskResponse>> getAllTasks() {
        List<TaskResponse> tasks = storage.values().stream()
                .map(this::toResponse)          // Task → TaskResponse (не отдаём модель напрямую)
                .collect(Collectors.toList());

        return ResponseEntity.ok(tasks);        // 200 OK + JSON-массив
    }

    // ═══════════════════════════════════════════════════════════════════════
    // GET /api/tasks/{id} — Получить конкретную задачу по ID
    // ═══════════════════════════════════════════════════════════════════════
    @GetMapping("/{id}")
    public ResponseEntity<TaskResponse> getTaskById(@PathVariable Long id) {
        Task task = storage.get(id);

        if (task == null) {
            // Задача не найдена — возвращаем 404 без тела ответа
            return ResponseEntity.notFound().build();
        }

        return ResponseEntity.ok(toResponse(task)); // 200 OK + JSON задачи
    }

    // ═══════════════════════════════════════════════════════════════════════
    // POST /api/tasks — Создать новую задачу
    // ═══════════════════════════════════════════════════════════════════════
    @PostMapping
    public ResponseEntity<TaskResponse> createTask(@RequestBody TaskRequest request) {
        // Генерируем уникальный ID атомарно (возвращает текущее значение, затем увеличивает)
        Long id = idCounter.getAndIncrement();
        Task task = new Task(id, request.title(), request.done());
        storage.put(id, task);

        // По стандарту REST (RFC 7231) ответ 201 Created должен содержать
        // заголовок Location с URL только что созданного ресурса.
        // Используем относительный URI — для production рекомендуется абсолютный
        // через ServletUriComponentsBuilder (см. врезку ниже).
        URI location = URI.create("/api/tasks/" + id);

        return ResponseEntity
                .created(location)              // 201 Created + заголовок Location
                .body(toResponse(task));        // + тело с созданной задачей
    }

    // ═══════════════════════════════════════════════════════════════════════
    // PUT /api/tasks/{id} — Полное обновление задачи (заменяем все поля)
    // ═══════════════════════════════════════════════════════════════════════
    @PutMapping("/{id}")
    public ResponseEntity<TaskResponse> updateTask(
            @PathVariable Long id,
            @RequestBody TaskRequest request) {

        Task task = storage.get(id);
        if (task == null) {
            return ResponseEntity.notFound().build(); // 404 если задачи нет
        }

        // PUT = полная замена: обновляем ВСЕ поля из запроса
        task.setTitle(request.title());
        task.setDone(request.done());

        return ResponseEntity.ok(toResponse(task)); // 200 OK + обновлённая задача
    }

    // ═══════════════════════════════════════════════════════════════════════
    // PATCH /api/tasks/{id} — Частичное обновление задачи
    // ═══════════════════════════════════════════════════════════════════════
    @PatchMapping("/{id}")
    public ResponseEntity<TaskResponse> patchTask(
            @PathVariable Long id,
            @RequestBody TaskPatchRequest patch) {

        Task task = storage.get(id);
        if (task == null) {
            return ResponseEntity.notFound().build(); // 404 если задачи нет
        }

        // PATCH = частичное обновление: меняем только те поля, которые переданы (не null)
        if (patch.title() != null) {
            task.setTitle(patch.title());
        }
        if (patch.done() != null) {
            task.setDone(patch.done()); // Boolean → boolean (автораспаковка)
        }

        return ResponseEntity.ok(toResponse(task)); // 200 OK + обновлённая задача
    }

    // ═══════════════════════════════════════════════════════════════════════
    // DELETE /api/tasks/{id} — Удалить задачу
    // ═══════════════════════════════════════════════════════════════════════
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteTask(@PathVariable Long id) {
        // Map.remove() возвращает удалённый объект, или null если ключа не было
        Task removed = storage.remove(id);

        if (removed == null) {
            return ResponseEntity.notFound().build(); // 404 — нечего удалять
        }

        return ResponseEntity.noContent().build(); // 204 No Content — успешно удалено
    }

    // ═══════════════════════════════════════════════════════════════════════
    // Вспомогательный метод: Task (внутренняя модель) → TaskResponse (DTO)
    // ═══════════════════════════════════════════════════════════════════════
    private TaskResponse toResponse(Task task) {
        return new TaskResponse(task.getId(), task.getTitle(), task.isDone());
    }
}
```

> **💡 Абсолютный URI в Location (production-подход)**
> 
> `URI.create("/api/tasks/" + id)` создаёт **относительный** URI. По стандарту RFC 7231 заголовок `Location` должен содержать **абсолютный** URI. Для production-кода используйте `ServletUriComponentsBuilder`:
> 
> Java
> 
> ```
> import org.springframework.web.servlet.support.ServletUriComponentsBuilder;
> 
> URI location = ServletUriComponentsBuilder
>     .fromCurrentRequest()   // берёт scheme, host, port из текущего запроса
>     .path("/{id}")
>     .buildAndExpand(id)
>     .toUri();
> // → http://localhost:8080/api/tasks/1
> ```
> 
> В учебном примере относительный URI допустим.

## 11. Тестирование Контроллера

> **[Уровень: Senior]**

### Почему @WebMvcTest, а не @SpringBootTest?

`@SpringBootTest` поднимает **весь** Spring-контекст (все бины, базы данных, очереди и т.д.) — это медленно. `@WebMvcTest` загружает только **веб-слой**: контроллеры, фильтры, `MockMvc`. Тесты запускаются в десятки раз быстрее.

`MockMvc` симулирует HTTP-запросы без реального сервера — вы пишете тесты как `curl`, но прямо в Java-коде.

> **💡 Синтаксис jsonPath**
> 
> text
> 
> ```
> $             — корень JSON документа
> $.id          — поле id на верхнем уровне объекта
> $.title       — поле title на верхнем уровне объекта
> $[0]          — первый элемент массива (индексация с нуля)
> $[0].title    — поле title первого элемента массива
> $             — сам массив (используется с hasSize())
> ```

Java

```
// src/test/java/com/example/taskmanager/controller/TaskControllerTest.java
package com.example.taskmanager.controller;

import com.example.taskmanager.dto.TaskPatchRequest;
import com.example.taskmanager.dto.TaskRequest;
import com.fasterxml.jackson.databind.ObjectMapper;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest;
import org.springframework.http.MediaType;
import org.springframework.test.annotation.DirtiesContext;
import org.springframework.test.web.servlet.MockMvc;

import static org.hamcrest.Matchers.hasSize;
import static org.hamcrest.Matchers.is;
import static org.hamcrest.Matchers.notNullValue;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.delete;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.patch;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultHandlers.print;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.header;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

// @WebMvcTest — загружает только веб-контекст (контроллеры + MockMvc).
// Не запускает сервер и не загружает сервисы/репозитории → тесты быстрые.
@WebMvcTest(TaskController.class)
// @DirtiesContext — пересоздаёт Spring-контекст (и вместе с ним TaskController)
// перед каждым тестом. Это необходимо потому что TaskController хранит данные
// в Map внутри singleton-бина. Без этого данные из одного теста "утекут" в следующий.
@DirtiesContext(classMode = DirtiesContext.ClassMode.BEFORE_EACH_TEST_METHOD)
class TaskControllerTest {

    // MockMvc симулирует HTTP-запросы без запуска реального сервера
    @Autowired
    private MockMvc mockMvc;

    // ObjectMapper сериализует Java-объекты в JSON-строку для тел запросов
    @Autowired
    private ObjectMapper objectMapper;

    // ═══════════════════════════════════════════════════════════════════════
    // GET /api/tasks — пустой список при старте
    // ═══════════════════════════════════════════════════════════════════════
    @Test
    @DisplayName("GET /api/tasks → возвращает пустой список при пустом хранилище")
    void getAllTasks_whenStorageEmpty_returnsEmptyArray() throws Exception {
        mockMvc.perform(
                get("/api/tasks")                         // выполнить GET /api/tasks
                    .accept(MediaType.APPLICATION_JSON))  // заголовок Accept: application/json
            .andDo(print()) // вывести полный запрос и ответ в консоль (удобно при отладке)
            .andExpect(status().isOk())                   // HTTP 200
            .andExpect(content().contentType(MediaType.APPLICATION_JSON))
            .andExpect(jsonPath("$", hasSize(0)));         // тело — пустой JSON-массив []
    }

    // ═══════════════════════════════════════════════════════════════════════
    // POST /api/tasks — создание задачи
    // ═══════════════════════════════════════════════════════════════════════
    @Test
    @DisplayName("POST /api/tasks → создаёт задачу, возвращает 201 + Location")
    void createTask_withValidRequest_returns201WithLocation() throws Exception {
        TaskRequest request = new TaskRequest("Изучить MockMvc", false);
        // objectMapper.writeValueAsString() → {"title":"Изучить MockMvc","done":false}
        String requestJson = objectMapper.writeValueAsString(request);

        mockMvc.perform(
                post("/api/tasks")
                    .contentType(MediaType.APPLICATION_JSON) // Content-Type: application/json
                    .content(requestJson))                   // тело запроса — JSON-строка
            .andDo(print())
            .andExpect(status().isCreated())                 // HTTP 201
            .andExpect(header().exists("Location"))          // заголовок Location присутствует
            .andExpect(jsonPath("$.id", notNullValue()))     // поле id не null
            .andExpect(jsonPath("$.title", is("Изучить MockMvc"))) // title совпадает
            .andExpect(jsonPath("$.done", is(false)));       // done = false
    }

    // ═══════════════════════════════════════════════════════════════════════
    // GET после POST — полный цикл: создать и получить
    // ═══════════════════════════════════════════════════════════════════════
    @Test
    @DisplayName("POST затем GET /api/tasks/{id} → созданная задача доступна по ID")
    void createThenGet_returnsCreatedTask() throws Exception {
        // Шаг 1: создаём задачу через POST
        TaskRequest request = new TaskRequest("Тестовая задача", false);
        String createResponseJson = mockMvc.perform(
                post("/api/tasks")
                    .contentType(MediaType.APPLICATION_JSON)
                    .content(objectMapper.writeValueAsString(request)))
            .andExpect(status().isCreated())
            .andReturn()
            .getResponse()
            .getContentAsString(); // получаем тело ответа как строку: {"id":1,"title":"..."}

        // Извлекаем ID из JSON-ответа через ObjectMapper
        Long createdId = objectMapper
            .readTree(createResponseJson) // парсим JSON-строку в дерево
            .get("id")                    // берём поле "id"
            .asLong();                    // конвертируем в Long

        // Шаг 2: получаем задачу по ID и проверяем поля
        mockMvc.perform(get("/api/tasks/" + createdId))
            .andExpect(status().isOk())
            // .value() корректно сравнивает числа независимо от их Java-типа (Integer/Long)
            .andExpect(jsonPath("$.id").value(createdId))
            .andExpect(jsonPath("$.title", is("Тестовая задача")))
            .andExpect(jsonPath("$.done", is(false)));
    }

    // ═══════════════════════════════════════════════════════════════════════
    // GET /api/tasks/{id} — задача не найдена
    // ═══════════════════════════════════════════════════════════════════════
    @Test
    @DisplayName("GET /api/tasks/9999 → 404 если задачи с таким ID нет")
    void getTaskById_whenNotFound_returns404() throws Exception {
        mockMvc.perform(get("/api/tasks/9999"))
            .andExpect(status().isNotFound()); // HTTP 404
    }

    // ═══════════════════════════════════════════════════════════════════════
    // DELETE /api/tasks/{id} — удаление с последующей проверкой
    // ═══════════════════════════════════════════════════════════════════════
    @Test
    @DisplayName("DELETE /api/tasks/{id} → 204, повторный GET возвращает 404")
    void deleteTask_thenGetReturns404() throws Exception {
        // Создаём задачу для удаления
        TaskRequest request = new TaskRequest("К удалению", false);
        String createJson = mockMvc.perform(
                post("/api/tasks")
                    .contentType(MediaType.APPLICATION_JSON)
                    .content(objectMapper.writeValueAsString(request)))
            .andReturn().getResponse().getContentAsString();

        Long id = objectMapper.readTree(createJson).get("id").asLong();

        // Удаляем задачу
        mockMvc.perform(delete("/api/tasks/" + id))
            .andExpect(status().isNoContent()); // HTTP 204 — успешно удалено

        // Проверяем что задача исчезла из хранилища
        mockMvc.perform(get("/api/tasks/" + id))
            .andExpect(status().isNotFound()); // HTTP 404
    }
}
```

> **💡 Важно знать: следующий шаг**
> 
> В реальном приложении логику хранения данных выносят в отдельный **сервисный слой** (`@Service`), а контроллер только принимает запросы и делегирует. В тестах с `@WebMvcTest` сервис мокируется через `@MockBean` — и проблема с состоянием singleton исчезает. Мы реализуем это в статье 6.5.

## 12. Типичные Ошибки

> **[Уровень: Junior / Middle]**

### Ошибка 1: 404 — Контроллер не найден

Bash

```
curl http://localhost:8080/api/tasks
```

JSON

```
{
  "timestamp": "2024-01-15T10:30:00.000+00:00",
  "status": 404,
  "error": "Not Found",
  "path": "/api/tasks"
}
```

**Причина A:** Нет аннотации `@RestController` на классе

Java

```
// ❌ Нет аннотации — Spring не регистрирует как бин
public class TaskController {
    @GetMapping("/api/tasks")
    public List<Task> getTasks() { return List.of(); }
}
// В логах Spring вы НЕ увидите: Mapped "{[/api/tasks],methods=[GET]}"
```

**Причина B:** Контроллер находится вне зоны сканирования

text

```
com.example.taskmanager.TaskManagerApplication  ← главный класс
com.other.controller.TaskController             ← ❌ не будет найден!
```

**Решение:**

Java

```
package com.example.taskmanager.controller; // ← правильный пакет

@RestController // ← обязательно
@RequestMapping("/api/tasks")
public class TaskController { ... }
```

### Ошибка 2: Пустые поля в JSON-ответе `{}`

Bash

```
curl http://localhost:8080/api/tasks/1
```

JSON

```
{"id": null, "title": null, "done": false}
```

В логах Spring вы ничего не увидите — это ошибка конфигурации Jackson, не исключение.

**Причина:** У Java-класса нет геттеров — Jackson не может прочитать приватные поля

Java

```
// ❌ Нет геттеров → Jackson видит только пустой объект
public class Task {
    private Long id;
    private String title;
    // Геттеры отсутствуют!
}

// ✅ Явные геттеры → Jackson находит getId(), getTitle()
public class Task {
    private Long id;
    private String title;
    public Long getId()      { return id; }
    public String getTitle() { return title; }
}

// ✅ Record — геттеры-аксессоры генерируются автоматически
public record TaskResponse(Long id, String title, boolean done) {}
```

### Ошибка 3: null в полях @RequestBody

Bash

```
curl -X POST http://localhost:8080/api/tasks \
     -H "Content-Type: application/json" \
     -d '{"Title": "Test", "Done": false}'
```

JSON

```
{"id": 1, "title": null, "done": false}
```

Ошибки в консоли нет — Jackson просто не нашёл поля с нужными именами.

**Причина:** Jackson по умолчанию чувствителен к регистру. Поле `"Title"` (с заглавной буквы) не совпадает с `title` в Java-классе.

Bash

```
# ❌ Неверный регистр первой буквы
-d '{"Title": "Test", "Done": false}'

# ✅ Точное совпадение имён полей в camelCase
-d '{"title": "Test", "done": false}'
```

### Ошибка 4: Дублирование слешей в пути — 404

Java

```
// ❌ Двойной слеш: итоговый путь /api//tasks → 404
@RequestMapping("/api/")   // слеш в конце базового пути
public class TaskController {
    @GetMapping("/tasks")  // слеш в начале пути метода
    public List<Task> getTasks() { return List.of(); }
}
```

Bash

```
curl http://localhost:8080/api/tasks
# → 404 Not Found (ожидается /api//tasks, а не /api/tasks)
```

Java

```
// ✅ Правильно: без слеша в конце базового пути
@RequestMapping("/api")
public class TaskController {
    @GetMapping("/tasks")  // итого: /api/tasks
    public List<Task> getTasks() { return List.of(); }
}
```

### Ошибка 5: Циклическая ссылка в JSON

text

```
com.fasterxml.jackson.databind.exc.InvalidDefinitionException:
Direct self-reference leading to cycle (through reference chain:
com.example.User["orders"]→com.example.Order["user"]→...)
Caused by: java.lang.StackOverflowError
```

**Причина:** Двунаправленная связь между объектами — Jackson рекурсивно сериализует `User` → `Orders` → `User` → ...

Java

```
// ❌ User.orders → Order.user → User → ... (бесконечная рекурсия)
public class User {
    private List<Order> orders; // Order содержит поле User user!
}

// ✅ Используйте DTO без циклических ссылок — передавайте только нужные данные
public record UserResponse(Long id, String name, List<Long> orderIds) {}
```

@Test
@DisplayName("PATCH /api/tasks/{id} → обновляет done, title остаётся")
void patchTask_updatesDoneField_returns200() throws Exception {
    // Создаём задачу
    String createJson = mockMvc.perform(
            post("/api/tasks")
                .contentType(MediaType.APPLICATION_JSON)
                .content(objectMapper.writeValueAsString(
                    new TaskRequest("Изучить PATCH", false))))
        .andReturn().getResponse().getContentAsString();

    Long id = objectMapper.readTree(createJson).get("id").asLong();

    // Выполняем частичное обновление: меняем только done
    mockMvc.perform(
            patch("/api/tasks/" + id)
                .contentType(MediaType.APPLICATION_JSON)
                .content(objectMapper.writeValueAsString(
                    new TaskPatchRequest(null, true)))) // title=null → не обновлять
        .andExpect(status().isOk())                              // HTTP 200
        .andExpect(jsonPath("$.done", is(true)))                 // done изменился
        .andExpect(jsonPath("$.title", is("Изучить PATCH")));    // title не изменился
}

@Test
@DisplayName("PATCH /api/tasks/9999 → 404 если задачи нет")
void patchTask_whenNotFound_returns404() throws Exception {
    mockMvc.perform(
            patch("/api/tasks/9999")
                .contentType(MediaType.APPLICATION_JSON)
                .content(objectMapper.writeValueAsString(
                    new TaskPatchRequest(null, true))))
        .andExpect(status().isNotFound()); // HTTP 404
}

### Таблица изученных аннотаций

|Аннотация|Назначение|Пример использования|
|---|---|---|
|`@RestController`|REST-контроллер: `@Controller` + `@ResponseBody` на каждом методе|На классе|
|`@Controller`|MVC-контроллер для работы с HTML-шаблонами|На классе|
|`@RequestMapping`|Базовый URL-путь для класса или конкретного метода|`@RequestMapping("/api/tasks")`|
|`@GetMapping`|Маппинг HTTP GET запроса|`@GetMapping("/{id}")`|
|`@PostMapping`|Маппинг HTTP POST запроса|`@PostMapping`|
|`@PutMapping`|Маппинг HTTP PUT запроса|`@PutMapping("/{id}")`|
|`@PatchMapping`|Маппинг HTTP PATCH запроса|`@PatchMapping("/{id}")`|
|`@DeleteMapping`|Маппинг HTTP DELETE запроса|`@DeleteMapping("/{id}")`|
|`@RequestParam`|Параметр из query string (`?key=value`)|`@RequestParam(defaultValue="10") int limit`|
|`@PathVariable`|Переменная из URL-пути (`/{id}`)|`@PathVariable Long id`|
|`@RequestBody`|Десериализация JSON из тела запроса в Java-объект|`@RequestBody TaskRequest request`|
|`@ResponseBody`|Сериализация возвращаемого объекта в JSON|На методе `@Controller`|
|`@ResponseStatus`|Декларативный HTTP-статус ответа|`@ResponseStatus(HttpStatus.CREATED)`|
