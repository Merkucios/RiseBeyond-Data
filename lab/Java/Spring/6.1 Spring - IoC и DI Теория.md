## Что ты создашь

Ты построишь **боевую систему** для текстовой RPG-игры CodeQuest.

На **Арене Зависимостей** герои сражаются с монстрами. Каждый бой управляется `CombatService`, который использует двух помощников: `DamageCalculator` (считает урон) и `LootGenerator` (генерирует добычу).

**Путь:**

- 🟢 **Сначала** — создаёшь все объекты руками через `new`. Чувствуешь боль жёсткой связанности.
- 🔵 **Потом** — находишь проблему, создаёшь новые реализации интерфейсов.
- 🟡 **Затем** — добавляешь Spring-аннотации. Контейнер берёт управление на себя.
- 🟠 **Дальше** — профили, `ApplicationContext`, конфигурация через `@Bean`.
- 🔴 **Наконец** — циклические зависимости и `BeanPostProcessor`. Магия контейнера изнутри.

**ВАУ-момент модуля:** В задании 3.1 ты добавишь несколько аннотаций — и Spring сам создаст и свяжет все объекты без единого `new` в твоём коде.

## Доменная модель: Боевая система CodeQuest

### RPG-описание

В мире CodeQuest существует **Арена Зависимостей**. Распорядитель арены (`CombatService`) проводит бои, используя двух помощников. **Мастер урона** (`DamageCalculator`) считает, сколько силы достигнет цели. **Хранитель сокровищ** (`LootGenerator`) решает, что оставит монстр после гибели.

Ключевой вопрос всего модуля: **кто создаёт этих помощников и передаёт их распорядителю?**

Сначала — ты сам, через `new`. Потом — Spring IoC Container, автоматически.

|Класс / Интерфейс|RPG-роль|Концепция IoC/DI|
|---|---|---|
|`DamageCalculator`|Контракт мастера урона|**DIP** — зависеть от абстракции, не от реализации|
|`SimpleDamageCalculator`|Простой удар без рандома|**Loose Coupling** — взаимозаменяемая реализация|
|`CriticalDamageCalculator`|Удар с шансом крита|**@Primary**, **@Bean** с параметрами|
|`LootGenerator`|Контракт хранителя сокровищ|Второй пример **DIP**|
|`BasicLootGenerator`|Выдаёт один обычный предмет|**@Component** — регистрация в контейнере|
|`RareLootGenerator`|Шанс легендарного трофея|**@Qualifier** — явный выбор реализации|
|`Hero`|Герой (record, чистый домен)|**Нет Spring** — доменные объекты без фреймворка|
|`Monster`|Монстр (record, чистый домен)|**Нет Spring** — чистый домен|
|`CombatService`|Распорядитель арены|**Constructor Injection** — главный паттерн DI|
|`CombatLog`|Летописец боёв|**Цепочка DI** — транзитивные зависимости|
|`GameConfig`|Кузница конфигурации|**@Configuration + @Bean**|
|`BrokenCombatService`|Ржавый меч (антипаттерн)|**Tight Coupling** — демонстрация проблемы `new`|
|`BrokenCircularA/B`|Древнее проклятие|**Circular Dependency** — ошибка при старте|
|`CombatTimingBPP`|Хранитель времени|**BeanPostProcessor** — расширение контейнера|

package com.codequest.ioc.model;

/**
 * Герой — участник арены.
 *
 * WHY: Java 17 record — неизменяемый DTO без boilerplate.
 * Никаких Spring-аннотаций: доменные объекты не зависят от фреймворка.
 */
public record Hero(String name, int hp, int attackPower) {

    public Hero {
        if (name == null || name.isBlank())
            throw new IllegalArgumentException("Имя героя не может быть пустым");
        if (hp <= 0)
            throw new IllegalArgumentException("HP должен быть > 0, получено: " + hp);
        if (attackPower <= 0)
            throw new IllegalArgumentException("Атака должна быть > 0, получено: " + attackPower);
    }

    public static Hero warrior(String name) { return new Hero(name, 100, 25); }
    public static Hero mage(String name)    { return new Hero(name, 70, 40);  }
    public static Hero rogue(String name)   { return new Hero(name, 85, 30);  }

    @Override
    public String toString() {
        return String.format("🧙 %s [HP:%d ATK:%d]", name, hp, attackPower);
    }
}

package com.codequest.ioc.model;

/**
 * Монстр — противник на арене.
 *
 * WHY: lootLevel определяет тип лута:
 *   1 = обычный монстр (BasicLootGenerator)
 *   2 = босс (RareLootGenerator)
 */
public record Monster(String name, int hp, int defense, int lootLevel) {

    public Monster {
        if (name == null || name.isBlank())
            throw new IllegalArgumentException("Имя монстра не может быть пустым");
        if (hp <= 0)
            throw new IllegalArgumentException("HP должен быть > 0");
        if (defense < 0)
            throw new IllegalArgumentException("Защита не может быть отрицательной");
        if (lootLevel < 1 || lootLevel > 2)
            throw new IllegalArgumentException("lootLevel: 1 или 2, получено: " + lootLevel);
    }

    public static Monster skeleton()   { return new Monster("Скелет-воин",      50,  3, 1); }
    public static Monster goblin()     { return new Monster("Гоблин-разведчик",  35,  1, 1); }
    public static Monster dragonBoss() { return new Monster("Дракон Сол'кар",   200, 15, 2); }
    public static Monster lichKing()   { return new Monster("Король-лич",        150, 10, 2); }

    public boolean isBoss() { return lootLevel == 2; }

    @Override
    public String toString() {
        return String.format("💀 %s%s [HP:%d DEF:%d]",
                name, isBoss() ? " [БОСС]" : "", hp, defense);
    }
}

package com.codequest.ioc.broken;

import com.codequest.ioc.model.Hero;
import com.codequest.ioc.model.Monster;

import java.util.List;
import java.util.Random;

/**
 * Сервис управления боем — ранняя версия.
 * Работает при запуске. Но что-то здесь не так...
 */
public class BrokenCombatService {

    private final BrokenSimpleCalculator damageCalculator;
    private final BrokenBasicLoot lootGenerator;

    public BrokenCombatService() {
        this.damageCalculator = new BrokenSimpleCalculator();
        this.lootGenerator = new BrokenBasicLoot();
    }

    public String fight(Hero hero, Monster monster) {
        int damage = damageCalculator.calculate(hero.attackPower(), monster.defense());
        boolean heroWon = damage >= monster.hp();
        List<String> loot = heroWon ? lootGenerator.generate(monster.name()) : List.of();
        return String.format("⚔ %s vs %s | Урон: %d | %s | Лут: %s",
                hero.name(), monster.name(), damage,
                heroWon ? "ПОБЕДА" : "ПОРАЖЕНИЕ", loot);
    }

    private static class BrokenSimpleCalculator {
        public int calculate(int attack, int defense) {
            return Math.max(1, attack - defense);
        }
    }

    private static class BrokenBasicLoot {
        private static final List<String> ITEMS = List.of("Монета", "Кость", "Трава");
        public List<String> generate(String name) {
            return List.of(ITEMS.get(new Random().nextInt(ITEMS.size())));
        }
    }
}

    static class FixedServiceA {
        private final FixedServiceB b;
        FixedServiceA(@Lazy FixedServiceB b) { this.b = b; }
        public int getWins(String name)       { return b.countWins(name); }
    }

    static class FixedServiceB {
        private final FixedServiceA a;
        FixedServiceB(FixedServiceA a)       { this.a = a; }
        public int countWins(String name)    { return 42; }
    }

    @Configuration
    static class LazyFixConfig {
        @Bean FixedServiceA fixedA(@Lazy FixedServiceB b) { return new FixedServiceA(b); }
        @Bean FixedServiceB fixedB(FixedServiceA a)        { return new FixedServiceB(a); }
    }

    static class SharedStats {
        private final java.util.Map<String, Integer> wins = new java.util.HashMap<>();
        public int get(String n)   { return wins.getOrDefault(n, 0); }
        public void add(String n)  { wins.merge(n, 1, Integer::sum); }
    }

        @Bean SharedStats shared()       { return new SharedStats(); }
        @Bean RefA refA(SharedStats s)   { return new RefA(s); }
        @Bean RefB refB(SharedStats s)   { return new RefB(s); }
    }

    private String getFullMessage(Throwable t) {
        if (t == null) return "";
        var sb = new StringBuilder();
        var cur = t;
        while (cur != null) {
            if (cur.getMessage() != null) sb.append(cur.getMessage()).append(' ');
            sb.append(cur.getClass().getSimpleName()).append(' ');
            cur = cur.getCause();
        }
        return sb.toString();
    }

<details> <summary>💡 Подсказка к 3.2 "Выбор оружия"</summary>

Когда у Spring два кандидата одного типа — ему нужна подсказка. Два способа:

1. **Один фаворит:** аннотация `@Primary` на одном из классов — он будет выбран по умолчанию.
2. **Явный выбор:** аннотация `@Qualifier("имяБина")` рядом с параметром конструктора — Spring выберет конкретный бин по имени.

Имя бина по умолчанию = имя класса с маленькой буквы: `CriticalDamageCalculator` → `criticalDamageCalculator`.

</details>

<details> <summary>💡 Подсказка к 3.3 "Два стиля боя"</summary>

В `@Configuration` классе каждый `@Bean`-метод — это "рецепт" создания объекта. Имя метода = имя бина в контексте.

Агрессивный рецепт: берёт `CriticalDamageCalculator` и `RareLootGenerator`, передаёт в `new CombatService(...)`.  
Оборонительный рецепт: берёт `SimpleDamageCalculator` и `BasicLootGenerator`.

Если нужно создать новые экземпляры прямо в методе — используй `new`.

</details>

<details> <summary>💡 Подсказка к 4.1 "Рефакторинг арены"</summary>

`CommandLineRunner` — это интерфейс с одним методом `run(String... args)`. Spring Boot автоматически вызывает все бины типа `CommandLineRunner` после старта. Объяви его как `@Bean` в `@Configuration`-классе. Используй lambda: `return args -> { /* логика арены */ }`.

Чтобы получить `CombatLog` из контейнера — добавь его как параметр `@Bean`-метода.

</details>

<details> <summary>💡 Подсказка к 4.2 "Гибкая арена"</summary>

`@Profile("easy")` на `@Bean`-методе означает: "создай этот бин только если активен профиль easy".

Создай два метода в конфиге (или два класса):

- `@Bean @Profile("easy")` → возвращает `SimpleDamageCalculator`
- `@Bean @Profile("hard")` → возвращает `CriticalDamageCalculator`

Оба возвращают тип `DamageCalculator` (интерфейс!). Spring выберет нужный по активному профилю.

</details>

<details> <summary>💡 Подсказка к 5.1 "Ловушка циклов"</summary>

Запусти и прочитай ошибку целиком — Spring покажет граф зависимостей.

**Лучшее решение (рефакторинг):** Что общего между `BrokenCircularA` и `BrokenCircularB`? Вынеси это в третий класс `SharedStatsService`. Тогда A → Shared и B → Shared, цикла нет.

**Быстрое решение (@Lazy):** На одной из зависимостей добавь `@Lazy` — Spring создаст прокси вместо реального объекта при создании бина. Реальный объект создастся при первом обращении.

</details>

<details> <summary>💡 Подсказка к 5.2 "Временная метка"</summary>

`BeanPostProcessor` — два метода:

- `postProcessBeforeInitialization`: вызывается ДО `@PostConstruct`
- `postProcessAfterInitialization`: вызывается ПОСЛЕ `@PostConstruct`

Для замера: запомни `System.currentTimeMillis()` в Before (в `Map<String, Long>` по имени бина). В After — вычти из текущего времени и выведи в лог.
